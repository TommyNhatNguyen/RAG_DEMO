1. Introduction

This document describes the system as implemented. It replaces older statements that generation was out of scope or that video used a uniform 3-frame / 15s OpenCV sampler with a silent duration cap.

In scope: ingest (Docling / text / image / video), dual Chroma collections, retrieval + score rerank, Vietnamese tutoring answers via Qwen3-1.7B, long-video coarse sampling and representative frame selection, checkpoints for Whisper/WAV reuse, SHA-256 incremental ingest.

Out of scope (not in this slice): UI, auth, HTTP API, vLLM/Ollama, Qwen3-VL as the chat model, unified single vector collection, quantization, interactive chat REPL (weights still reload per ask process), HF_LOCAL_FILES_ONLY flag, benchmark/ingest-video CLI variants from the long-video prompt.

Do not mix Qwen3-Embedding and Qwen3-VL-Embedding in one collection. Do not load the LLM on ingest/search/stats. Retrieval returns list[RetrievalResult], not LangChain Documents. OCR is preprocessing, not an embedder. Binaries stay on disk; Chroma holds paths. project_root is cwd().

Video ───────── FFmpeg WAV + Whisper (CPU int8)
            └── coarse frames → pHash / OCR / optional PySceneDetect
            └── 1–3 frames / 30s window ── VL ── visual (video_frame)
            └── transcript windows ────── text ── text (metadata video_segment)

                                            retriever merge + score sort

Ingestion, retrieval, and generation are separate packages. Factory wires them. LLM loads only on first generate. VL loads only if visual search/index runs. Text embedder also lazy-loads.

7. Identifiers and incremental ingest

Document identity is SHA-256 of bytes (1 MiB chunks). Paths and names are NFC-normalized. If a path is outside project_root, relative_posix stores the filename only.

Vector ID encoding

Id patternMetadata content_typechunk_index
{hash}:text:{n}textsequential from TextChunker
{hash}:text:{n}video_segmentwindow index (id kind is text, not video_segment)
{hash}:text:{10000+i}textOCR sidecar from pictures/pages
{hash}:table:{n}tableDocling table index
{hash}:image:{n}imagepicture index or 0 for standalone
{hash}:page:{page}pagepage number
{hash}:video_frame:{ms}video_frameround(timestamp×1000), +1 on collision
Video transcript vectors use vector_id(id, "text", window_index) while metadata content_type is video_segment. Do not assume the id’s middle token equals content_type.

Skip / reindex rules

  • Same hash already in the current ingest batch → skip (duplicate files in one tree).
  • Same path, different hash → delete old vectors + object prefixes (images/, frames/, audio/{id}.wav, videos/, tmp/) + manifest hash; status reindexed_changed.
  • Non-video: skip if manifest has hash and Chroma has vectors in either collection.
  • Video: skip only if is_video_complete(hash, target_duration) and vectors exist. Complete means same video_pipeline_version and processed_duration + 1.0 ≥ target. Target is min(probed, cap) when cap is set.
  • Incomplete / old pipeline video: delete Chroma vectors only (keep WAV/transcript if checkpoint still matches duration); status reindexed_changed.

8. Metadata

base_metadata() always writes: document_id, source, file_name, filename (duplicate of file_name), relative_path, file_type, content_type, chunk_index. None values dropped. Non-scalars stringified for Chroma (flatten_metadata allows str/int/float/bool only).

Extras by type: text/table/page → page_number, section, image_path, caption. Video segment → video_id, start_time, end_time. Video frame → those plus timestamp, segment_id, image_path.

Manifest extra for video: processed_duration, video_pipeline_version, candidate_frames, selected_frames.

Video DocumentAsset.file_type is forced to mp4 in IndexingService.index_video even for .mov/.mkv. Manifest file_type still uses the real suffix.

9. Per-modality ingest (non-video)

PDF / DOCX / PPTX — DoclingLoader

  • Docling PdfPipelineOptions: do_ocr=False, do_table_structure=True, picture/page images from settings, images_scale=1.0.
  • Text iterate skips PAGE_FOOTER, PAGE_HEADER, FOOTNOTE, PICTURE, TABLE. TITLE / SECTION_HEADER become section.
  • Tables: export_to_markdown; empty markdown skipped.
  • Pictures always stored as PNG under storage/images/{id}/picture_NNN.png.
  • Page images stored for every PPTX page, or for any page whose native text is shorter than MIN_NATIVE_TEXT=40.
  • If no page has ≥40 native chars and page images exist, Tesseract runs on page images and OCR text is appended as extra text blocks.

TXT / Markdown — TextLoader

UTF-8 with replace. Markdown ATX headings (#{1,6}) split sections; heading line itself is not stored as a block. Plain TXT is one block.

Images — ImageLoader

Pillow RGB (alpha flattened onto white). Stored as storage/images/{id}/original.png. OCR text becomes both a text block and ImageAsset.ocr_text.

Text chunking

RecursiveCharacterTextSplitter(chunk_size, chunk_overlap). Blocks shorter than chunk_size stay whole. Empty parts dropped.

10. Long video

Default: process the full probed duration. Empty VIDEO_MAX_DURATION = no cap. If set and probed duration exceeds it, logs WARNING, records processed_duration, does not silently pretend the file is fully indexed.

[1/7] metadata (ffprobe: duration, size, fps, has_audio)
[2/7] audio WAV 16 kHz mono pcm_s16le (reuse if checkpoint matches)
[3/7] faster-whisper CPU int8 → timestamped pieces → transcript.json
[4/7] coarse JPEG every 10s (storage/tmp/{id}/candidates/candidate_NNNNNN.jpg, q=5)
[5/7] SemanticFrameSelectionStrategy (pHash, OCR interval, optional scenes, temporal spread)
[6–7] index: text windows + VL on selected frames only; delete tmp candidates; stage=indexed

Checkpoints

Work dir storage/videos/{sha256}/: checkpoint.json, transcript.json. WAV at storage/audio/{sha256}.wav. Stages: metadata → audio → transcript → coarse_frames → selected → indexed. Reuse requires same video_id, pipeline v2-long, and processed_duration within 1.0s. If checkpoint does not match, WAV/transcript/tmp candidates are deleted and the job restarts.

Whisper has no MPS; CTranslate2 CPU. Progress logs every ~10% of processed duration. Audio extract applies FFmpeg -t when capped; Whisper then reads that WAV.

Windows and transcripts

build_time_windows(processed, VIDEO_SEGMENT_DURATION) produces contiguous [start, end) slices. Each Whisper piece is assigned to the window that contains its start time (full text, no mid-sentence clip). transcript_for_window (overlap join) exists but is unused by the loader.

Frame selection

Average-hash 8×8. Near-duplicates skipped when similarity ≥ VIDEO_FRAME_SIMILARITY_THRESHOLD (0.90). Score:

0.35 * visual_change + 0.30 * ocr_change + 0.20 * scene_boundary + 0.15 * temporal_coverage

Cap VIDEO_MAX_REPRESENTATIVE_FRAMES (3) per window. If selection is empty, fallback strides coarse frames using VIDEO_FRAMES_PER_SEGMENT. Selected JPEGs copied to storage/frames/{id}/t{ms:09d}.jpg.

OCR on coarse frames at most every VIDEO_OCR_INTERVAL (30s) when enabled. Failure is logged; abort only if OCR_REQUIRED=true. PySceneDetect ContentDetector when VIDEO_SCENE_ENABLED=true; import/runtime failure returns no boundaries.

Do not VL-embed every coarse frame. Frame extraction is cheap; VL is expensive.

11. Indexing

IndexingService.index_document: batched text embed of chunks + tables + OCR strings; VL on pictures/pages. VL failure keeps text (exception logged). Visual payload is a path string, or {"text": caption|ocr, "image": path} when text exists. Page vs image distinguished by :page: in the image id.

index_video: one text vector per window with non-empty transcript; one visual vector per selected frame. After success, checkpoint stage indexed and storage/tmp/{id} is deleted.

Chroma add skips ids that already exist (chunked get of 100). Returns (added, skipped).

Embeddings: lazy load, normalize, trust_remote_code. Text query uses instruct prefix. VL query prompt: “Retrieve relevant documents for the query.” Text dtype follows device via LangChain; LLM uses float16 on mps/cuda and float32 on CPU.

12. Retrieval

process_user_query: NFC, collapse whitespace, strip most Unicode control chars (keep newline then strip). Empty after process → ValueError.

MultimodalRetriever.search: k defaults to retriever_k. Dual kNN unless include_visual=False or VL embedder is None. Merge by id (keep max score). ScoreReranker sorts descending. Return top k. VL search failure → text only (logged).

Empty collections return no hits. Query k is min(k, collection count).

13. Generation

GenerationService consumes list[RetrievalResult]. k = max(retriever_k, generation_k) unless CLI -k. Stores last_hits for --show-hits.

  • Model: Qwen/Qwen3-1.7B, enable_thinking=False via patched apply_chat_template passed into ChatHuggingFace (must pass the patched tokenizer, not a second copy).
  • max_new_tokens=4096, do_sample=False, generation_config.max_length=None on model and pipeline.
  • low_cpu_mem_usage=True; tries dtype= then falls back to torch_dtype=.
  • generate_answer blocking; generate_answer_stream prints tokens; iter_answer_tokens yields filtered chunks. Protocol aliases: generate / stream.
  • ThinkStreamFilter hides leftover <think> while streaming (holds last 6 chars; if stuck in think >8000 chars, keeps last 200). strip_think on the final string.
  • Context: format_hits (type, relative_path, page, times, chunk #); sources unique relative paths. Visual-only empty body uses a stub line. Absolute paths reduced to basename. 1.7B does not receive image pixels.
  • Prompt: Vietnamese UIT tutor; cite relative paths; no invented http URLs; no internal chain-of-thought.

Missing extra → RuntimeError instructing pip install -e ".[generation]" or ".[all]". Injected chat_model in tests bypasses Hugging Face.

15. Hugging Face cache vs RAM

Weights live under ~/.cache/huggingface/hub/models--Qwen--* after the first download (Embedding-0.6B ~1.2 GB, 1.7B ~4.1 GB, VL-2B ~4.3 GB). Subsequent ask commands reuse the cache. Hub 404 on sentence_bert_config.json etc. is optional probing. Loading weights: N/N in a few seconds is disk→MPS, not a re-download.

Each CLI process starts empty RAM, so 1.7B still loads ~5s per ask. Text and VL embedders are also per-process lazy singletons. HF_HUB_OFFLINE=1 skips HEAD/GET after the cache exists. There is no HF_LOCAL_FILES_ONLY setting and no persistent REPL.

16. Configuration

Settings via pydantic-settings: env file .env, case-insensitive, extra ignored. Empty string for tokens and VIDEO_MAX_DURATION becomes None. Relative paths resolve against project_root (cwd).

resolve_device: requested mps/cuda fall back to cpu if unavailable; unknown preferred tries mps then cuda then cpu. Missing torch → cpu.

See .env.example and README table. Selection weights exist on Settings even if not all are copied into .env.example.

Reset index: rm -rf data storage (keep assets). Backup triple: chroma + manifest + storage. Video checkpoints under storage/videos/{id}/.

Troubleshooting: Python 3.14 unsupported; MPS OOM → --text-only / DEVICE=cpu; FFmpeg missing → clear error; Tesseract missing → disable video OCR; thinking ON wastes tokens; Hub 404 probes are normal; ask reload is RAM, not re-download.

20. Known limitations

  1. No HTTP API, UI, or multi-turn chat process.
  2. Reranker is cosine sort, not a cross-encoder.
  3. Queries are text-only (no image-as-query).
  4. Video file_type metadata forced to mp4; transcript vector ids use kind text.
  5. Whisper CPU-only; CTranslate2 has no MPS.
  6. PySceneDetect off by default.
  7. Object-store keys not sandboxed against ...
  8. Manifest is single-process JSON (no file lock).
  9. Each ask reloads LLM into RAM from cache; Hub login on every command if token set.
  10. LLM may still hallucinate details even with citations in the prompt.
  11. Leftover OpenCV sample_frames is not on the ingest path.
  12. No HF_LOCAL_FILES_ONLY; rely on HF_HUB_OFFLINE=1.
  13. Coarse-frame reuse reconstructs timestamps as index * interval, not stored stamps.
